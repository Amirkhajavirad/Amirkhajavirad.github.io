Hardware: getting sensors, motors and wiring to agree

The lab’s rehabilitation robots run on a Raspberry Pi and a set of parts that have to agree with each other: RFID readers, HX711 load cells, photo interrupter sensors, a stepper motor and pellet delivery hardware. I developed and refined that platform until an operator could run it from a touchscreen.

  • Debugging across the boundary

    Tracked down faults in GPIO, SPI and UART communication, RFID readers, load cells, stepper motors, PCB connections and wiring, including differences between Raspberry Pi 4 and 5.

  • Calibration an operator can follow

    Refined the calibration for motor homing, pedestal positioning, pellet sensors and load cell zeroing, with guided steps, safety checks and a diagnostic for each way it can fail.

  • Standalone and Shuttle modes

    Implemented and validated both operating modes. Shuttle Mode changes how a pellet is presented after an outcome, while the RFID, sensing, analysis and logging pipeline stays the same.

  • Rigs outside the robot lab

    A biomechanical test platform for distal biceps tendon fixation, and an Arduino lighting controller for neonatal incubators.

Software: a touchscreen operators can trust

The robots are run by lab staff between experiments, so the interface has to be hard to misuse. I built the Python and Tkinter application that starts and stops the robot, manages RFID tags, sets up experiments, shows live status and walks the operator through calibration and updates. It is roughly 19,000 lines.

  • One button per step

    Redesigned the Software Update screen from 9 buttons and 13 information rows into a guided flow. It reuses the existing safety gates, so the redesign can delay a button but never enable an install early.

  • Built for touch

    A scrollable RFID picker that tells taps from drags, an on-screen QWERTY keyboard, a validated configuration editor with atomic writes, and live countdown timers for limits.

  • Interface and hardware kept apart

    The touchscreen talks to the control logic through runtime state files and file-based inter-process communication, so operator controls never sit in the hardware loop.

  • Bugs that were eating valid trials

    Fixed backend faults that discarded valid trial attempts (event ordering, dropped pending input, index errors) and a crash report that named the wrong robot. An audit of the logging found about 240 silently swallowed exceptions, and I designed a structured diagnostics plan to replace them.

Network and deployment: updates that refuse to break a robot

A fleet is only useful if every unit can be updated safely without someone visiting each one with a laptop. I designed and shipped a secure over-the-air update pipeline for the fleet, which is growing from 5 units to a planned 12, then tested every way it can fail.

Break something

    • Two gates, one approval

      A tag-triggered GitHub Actions workflow builds and validates the package, computes its SHA256 checksum, writes a production manifest and publishes a draft release, which is the single human approval gate. On the robot, nothing installs or reboots without operator confirmation, and I tested the full flow with a real remote install and reboot on hardware.

    • Least privilege

      The client is plain Python standard library. Each robot has its own read-only, single-repository token, so one can be revoked without touching the rest, and a regression scanner checks every log and status file for leaked secrets.

    • Tests for the bad days

      Mocked-network suites cover rejected authentication, a network drop mid-download, a checksum mismatch and a malformed manifest. They caught bugs before hardware testing, including a network error that was being reported as a disk error.

    • Faster checks, same results

    • Robots that talk to each other

      Advanced the TCP protocol for multi-robot coordination: RFID transfer, outcome messages, acknowledgements and duplicate protection. Also traced unstable eduroam (WPA2-Enterprise) Wi-Fi on NetworkManager through journalctl and nmcli, then added persistent auto-reconnect and a Forget Network control.

    Data: analysis you can audit

    Biomechanical testing platform for distal biceps fixation

    Master’s capstone, University of Alberta. September to December 2025

    A standardized rig for comparing unicortical and bicortical cortical button fixation of the distal biceps tendon, combining 3D printed anatomical bone models and custom fixtures with a BOSE ElectroForce mechanical testing system.

    • Implemented cyclic loading and pull-to-failure protocols based on the biomechanical literature.
    • Built the workflow around reproducibility, to reduce variability between specimens and make the two fixation methods quantitatively comparable.
    • Presented as a poster, “Testing of Repair Techniques for Distal Biceps Tendon Tears,” at the University of Alberta engineering research symposium.

    SolidWorks, 3D printing, BOSE ElectroForce

    Adaptive circadian lighting for neonatal incubators

    Undergraduate capstone. May to June 2022

    An embedded system that shifts incubator lighting through a day and night cycle suited to premature infants. I wrote the C++ firmware on Arduino, integrated the electronics and delivered the first working prototype.

    • Developed the microcontroller control logic for dynamic light regulation.
    • Validated the hardware through testing, debugging and performance checks.

    C++, Arduino, circuit design, hardware prototyping

    Clinical data analysis for a supportive oncology study

    April to June 2026

    Analysis of repeated hematologic measurements and chemotherapy-related adverse events in 34 breast cancer patients receiving melatonin or placebo, built as auditable Excel workbooks with publication-ready figures. (The graphic on the card is an illustration, not study data.)

    • Validated and cleaned the data, normalized units and reviewed missing values. Found and corrected inconsistent white blood cell count scaling while keeping the original source values, so every change can be traced.
    • Followed white blood cell count, hemoglobin and platelet count across four treatment measurements at patient and group level.
    • Evaluated neutropenia incidence, chemotherapy delays, G-CSF use and hospitalization for neutropenia with fever or infection.
    • Calculated proportions, risk estimates, 95% confidence intervals and Fisher’s exact tests, which suit outcomes with low event counts.
    • Produced longitudinal trend plots, baseline-adjusted change plots, risk plots and 100% stacked distribution charts.

    Excel, statistics, data validation, visualization

    Breast cancer subtype classification from microarray data

    Graduate course project. January to April 2025

    Classification of six tumour subtypes from a high-dimensional dataset (GSE45827): 151 biopsies measured across 54,676 genes. The best models reached up to 96% accuracy and 94% macro F1 across 5-run cross-validation.

    • Reduced dimensionality with PCA, Kernel PCA and LDA, and used correlation and Random Forest feature importance to deal with multicollinearity.
    • Compared SVM, Random Forest, KNN, Logistic Regression and Gaussian Naive Bayes.
    • Used Local Outlier Factor for outlier detection and compared training and test performance to check for overfitting.

    Python, scikit-learn

    PredictIQ: football match outcome prediction

    Team project, two members. September to December 2025

    An end-to-end machine learning pipeline covering data extraction, feature engineering, training and evaluation. The tuned XGBoost model reached a macro F1 of 0.357 and beat the baseline models.

    • Designed time-aware validation to prevent data leakage and to mimic real prediction conditions.
    • Used SHAP to explain model behaviour and show which features mattered.

    Python, XGBoost, SHAP

    About

    I like the part of engineering that starts after the design review. Sensors drift, wiring works loose and a network drops halfway through a download. My work sits between biomedical research and the machines and software it depends on.

    My MSc in Biomedical Engineering at the University of Alberta ended with a testing platform for distal biceps tendon fixation. Since November 2025 I have been building and maintaining the Raspberry Pi robots in a rehabilitation research lab, from calibration and touchscreen software to the update pipeline that keeps a growing fleet current.

    I also work with clinical and experimental data, most recently a longitudinal hematology dataset from a supportive oncology study. Lately I have been reading about humanoid robotics, especially systems that have to cope with uncertainty in real environments.
